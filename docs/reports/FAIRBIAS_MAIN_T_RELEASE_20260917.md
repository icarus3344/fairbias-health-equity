## 启动前发现并解决的环境问题

基础 `.venv311` 不含 TensorFlow，直接进行混合方法评价会在 FRAPPÉ 模型反序列化时失败。实际训练曾使用既有 FRAPPÉ 隔离环境；本次复用其解释器，并显式加入原基础库和已固定的可选依赖路径，没有安装或升级软件，也没有修改模型或科研源码。

组合环境的 Python、NumPy、SciPy、pandas、scikit-learn、joblib、fairlearn、torch 等研究冻结字段与原文档完全相同。另把 TensorFlow 2.14.0、模型修正依赖、Keras 等额外依赖的版本清单、解释器二进制哈希和路径环境绑定到执行计划。执行前后均核对依赖版本清单。

按“方法、预测器、运行版本、研究臂”的分组，选择字典序首个作业，完成 **110 个代表模型**的真实文件重载及身份核验。未重拟合、未生成预测、未读年度数据。该检查支持混合环境重载兼容性，不保证所有模型对真实 T 的预测均成功。证据：`fairbias_recovery_20260917/evidence/combined_runtime_reload_20260917.json`。

FairGBM 重载时的提示涉及无法继续训练；本流程只推断，不尝试恢复训练。TensorFlow 的 CUDA 注册提示不代表需要 GPU，本次显式禁用 CUDA。

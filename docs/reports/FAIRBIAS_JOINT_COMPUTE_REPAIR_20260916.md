# Joint 计算预算诊断与独立加速验收

本轮结论：已定位主要实现瓶颈并完成独立加速路径。最终 v2 的真实 F/C 相同搜索前缀从 94.25 秒降至 35.91 秒，约 2.62 倍；这不是完整 Joint 实验的加速倍数，也不表示 Joint 已在原预算内完成。现有正式队列、70 个登记源码/配置文件及旧结果均保留。

## 1. 已核实的主要原因

诊断对象固定为 arm_003 / LR / seed 0，候选 `cc84d0d23c1bc5af275d`。原正式尝试在 1,800 秒退出。选择依据是其超时状态，没有查看 S 的预测表现。F 有 21,871 人，C 有 5,580 人。

180 秒带 profiler 的独立试跑显示：

| 项目 | 累计时间/数量 | 含义 |
|---|---:|---|
| 完整几何评估 | 172.36 秒 | 约占本次拟合时间 95.8% |
| MDS 拟合内部 | 约 169.26 秒 | 几何耗时的主要来源 |
| 应力弯头维数搜索 | 136.39 秒 | 包含在上述几何/MDS时间内 |
| Shapley 距离构造 | 1.11 秒 | 优化这部分不是本次的主要突破口 |
| 模型效用评估 | 1 次，1.70 秒 | 并非预测模型训练占满运行时间 |
| MDS 内部欧氏距离调用 | 502,234 次 | 反复处理很小的浮点数组 |

这些时间是互相包含的调用时间，不能相加。Profiler 自身有开销，不能把这张表的每秒吞吐直接外推到正式任务。

`src/fairbias/bias_metric.py:438` 的弯头搜索对多个维度分别拟合 MDS；`:539` 还运行最终的四次初始化 MDS。这里的点是“特征加原点”，不是将两万名受访者组成全量两两距离矩阵。每次小矩阵迭代都经通用 dataframe/sparse/array API 检查；这类调用重复数十万次后，检查开销变得很大。

`src/fairbias/enhancement.py:711` 和 `:996` 已经先判断几何，再拟合候选模型。本轮没有发现“先训练大量不合格候选模型”是主因。Joint 在每次 BM 之后都搜索 AE（`src/nhis_fairbias/benchmark/adapters/adapter_fairbias_ae.py:280`）；当当前几何仍未满足严格阈值时，AE 可能遍历许多候选后一个也不接受。跳过这些 AE 搜索会改变 Joint 的路径，不能伪装成纯性能优化。

## 2. 已实现的改动

新增 `src/nhis_fairbias/benchmark/joint_budget_optimization.py`，正式 worker 没有导入它。

1. **MDS 数组专用检查路径**（`:134` 附近）：仅处理内部普通 float64、二维、非空、有限、限定尺寸的默认自距离调用。每次仍检查有限性，继续调用同一个 sklearn 数值内核。其他输入走原有校验；没有启用全局 assume-finite，也没有改写距离公式、SMACOF 更新或收敛判据。
2. **固定运行环境准入**（`:156`）：检查 sklearn 1.9.1 及三个关键函数的源码 SHA；未知版本拒绝进入加速路径。记录 NumPy、pandas 版本。不能宣称这一私有接口适配对其他版本天然成立。
3. **完整几何结果缓存，最终默认关闭**（`:82` 附近）：最多 128 项，只缓存完整、有限的成功结果；绑定实际输入值、索引、类型、保护属性、权重、特征顺序和全部几何参数；返回副本，不缓存接受/拒绝决策。未指定或可变 RNG 禁止复用。只在独立进程本次上下文内使用。较长试跑证明本例命中率低，哈希成本高于复用收益，因此最终 `joint_exact_geometry_v2` 默认只启用 MDS 专用检查加速；缓存保留为可测试的可选项。
4. **异常退出恢复与进度证据**：所有 hook 在 finally 中恢复。新增 `scripts/diagnose_joint_budget.py`，独立目录逐行写入阶段、调用次数、几何结果哈希和 BM 状态哈希，记录时间上限及最终状态。它不产生 S/T 评价或正式选优结果。

缓存保持适配器原有“逻辑几何调用”预算计数；真实 MDS 拟合数另计，缓存命中不虚构 MDS 运行记录。本次 16 次真实前缀没有缓存命中，不能把实测加速归功于缓存。非删除的 BM 接受路径存在重复几何计算（`src/fairbias/mitigation.py:267`、`:553` 和适配器 `:232`）；这一复用已另用真实引擎合成样本验证。

曾做 Shapley 计算计划缓存原型，因实测占比很小，没有启用或部署到正式执行路径。

## 4. 三类预算必须分别处理

| 预算/停止机制 | 当前问题 | 处理原则 |
|---|---|---|
| 每项 1,800 秒墙时 | 当前多数 Joint 退出的直接原因 | 先消除实现开销；重跑必须有新版本和新回执 |
| 最多 10 次 AE 提交 | 达到第十次后，在证明是否还有候选前就退出 | 这是保守的未完成判定；不能靠提高计算速度消除 |
| 单次 MDS 迭代上限 | 某些几何未证实收敛 | 保留失败，不能把迭代上限当作收敛 |

另有 50 次 BM 提交、500 次效用评估、20,000 次逻辑几何调用。一次逻辑几何会包含多次 MDS，不能把 20,000 理解成同等数量的模型训练或 MDS 拟合。

**P1 待单独修复：候选 MDS 预算异常的传播。** `src/fairbias/enhancement.py:277` 的广泛异常捕获会把候选 MDS 迭代上限变成候选拒绝；最终状态若恰好可行且能重新计算，可能报告 `STRICT_FEASIBLE_SEARCH_EXHAUSTED`，尽管有候选的几何没有评估完成。BM 不会这样吞掉该错误。真实已完成的 19 项 BM_AE VALID 记录中，本次检查没有发现 MDS cap 记录；这是潜在代码路径，不能说这些已有结果已受污染。

这与全局几何调用超限不同：即使 AE 暂时吞掉全局超限，最后的刷新仍会超限并失败。第十次 AE 提交后的预算退出也不是“虚假收敛”，而是没有证明搜索停止。

## 5. 较长试跑与后续决定

独立 F/C 试跑预先限时 600 秒，其他科学预算保持登记值，结果为 `DIAGNOSTIC_TIME_LIMIT`。它是诊断，不是原正式 1,800 秒任务的完成回执；不能据此断言加速后仍必然不能在 1,800 秒内完成。

- 发起 301 次逻辑几何评估，最后一次被诊断时限中断；完成 4 次 BM 提交，进入第 4 次 AE 搜索，AE 提交数为 0。
- 288 个已经形成审计记录的 AE 候选全部因 `EXCEEDS_FAIRNESS_CAP` 被拒绝。第 1 次 AE 从 8.93 秒运行到 206.28 秒，结束后正常进入第 2 次 BM；没有证据说明程序死锁。
- 4 次预测效用评估合计约 3.04 秒；几何约 523.65 秒。加速后，搜索范围本身仍然是主要成本。
- 共 4,719 份已完成 MDS 回执，均 `CONVERGED_BEFORE_CAP`。约 900 万次内部欧氏距离调用。回执内的 n_iter_ 是每次 MDS 最佳初始化的迭代数，不能将其简单相加称为所有初始化的实际总迭代数。
- 几何缓存命中 6 / 301 次；哈希约 28.48 秒，复用的历史计算耗时约 9.46 秒。后者只是记录的复用估计，尚未计缓存管理成本；因此关闭默认缓存有直接证据支持，而不能宣传“缓存一定加速”。
- 最大 RSS 约 727 MiB；记录 user CPU 约 596 秒。没有内存耗尽；所有 70 个登记源码和本次优化源码的运行前后校验一致。

**本轮验收范围：MDS 实现加速与独立诊断工具可用于下一版受控补跑；Joint 的完整预算问题尚未关闭，当前正式批次仍使用原版本。** 没有从这次诊断生成新的正式模型、S/T 成绩或论文优越性结论。

后续分两条处理：

- **等价实现补跑**：在新的源码身份和独立运行目录登记这次加速，保留原 40 项 Joint 与 BM_AE 的完整种子要求，不挑选成功种子拼接，不覆盖旧 TIME_LIMIT。先证明各配置运行可行，再用于冻结和论文结果。
- **预算方法学修订**：若仍到达提交上限或墙时，应预先决定是坚持完整搜索停止，还是另做“固定预算下最后一个已验证可行解”的敏感性分析。后者必须标记预算耗尽、未证实收敛，不能与原严格收敛结果混称；需要保留失败、可行性、运行成本和所有种子。不能单纯不断调高上限直到 FairBias 的 S 指标最好。

不将 Joint 改成先完成全部 BM 再运行 AE，不切换固定二维 MDS，不跳过不利候选，不修改当前批次。FairBias 主比较队列可以继续，本轮诊断不会把 Joint 的超时转写成主方法优越性证据。

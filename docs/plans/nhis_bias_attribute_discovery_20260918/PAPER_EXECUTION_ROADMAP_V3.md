## 1. 最终目的与边界

本项目的最终工作目标是形成一套可复核、可重现、主张与证据逐项绑定的论文投稿包，并在作者完成科学、伦理和数据责任审批后投稿。研究主轴固定为：有限 anchor 属性审计是否会高估去偏方法的有效性，以及扩展审计是否改变对同一固定模型或方法的判断。

“投稿就绪”和“发表成功”必须分开：项目团队可以控制研究设计、执行质量、透明报告、投稿和修订；编辑送审、审稿结论和最终录用由期刊决定，不能被任何 Agent 保证。负结果、方法不获胜或证据不足不会自动终止论文，只会限制可写主张。

当前不是 paper-ready。现状为 A0 有限通过、A1 科学内容未冻结、A2 仅通过合成合同验证；不得把这些状态写成新的 NHIS 实证发现。

## 2. 双 Agent 与人类监督的职责

| 工作 | Worker | Reviewer Agent | Human/Supervisor |
|---|---|---|---|
| 按当前 gate 实现、运行获准测试、保存证据 | R | I | A |
| 独立复核 diff、hash、对齐、测试和主张边界 | C | R | A |
| 给出 gate 的 Accept/Repair/Reject 建议 | I | R | A（最终决定） |
| 应用场景、delta、正式 O、分组/参照、确认性主张 | 禁止自行决定 | C | R/A |
| 伦理、数据权限、作者资格、AI 披露 | I | C | R/A |
| A4 是否开启、2025 是否一次性解锁 | 禁止自行决定 | C | R/A |
| 文稿、表图、可重现包的技术生产 | R | C | A |
| 选择期刊、批准投稿、回复审稿意见 | C | C | R/A |

`R` 为执行责任，`A` 为最终负责，`C` 为审阅/咨询，`I` 为知会。Reviewer 不代替人类领域判断；Worker 不自批准 gate。每个 gate 都遵循“Worker 交付 -> Reviewer 独立核验 -> Human/Supervisor 决定 -> 才进入下一 gate”。

## 3. 面向论文的阶段路线

### P0：治理与证据账本

进入条件：v3 计划、handoff、decision log 和仓库协议可定位。
工作：绑定 branch/HEAD、受保护基线、输入 hash、角色、门禁状态、2024 已知结果身份和 2025 锁。
退出条件：Reviewer 能从机器清单复算当前状态，且不存在把历史结果当新验证的表述。
当前状态：已建立基础材料，但本路线图和新增清单仍待独立审查。

### P1：A1 科学冻结

进入条件：A0 资产表和 A2 合成合同可用。
工作：完成 2022/2023 官方年度元数据绑定；由人类确认应用场景、delta、正式 O、分组、参照、嵌套/相关处理、确认性方法对和允许主张的角色；生成完整 contrast-level family manifest。
退出条件：`A1_FREEZE_CHECKLIST_V3_DRAFT.json` 所有 A1 必需项有证据且经 Reviewer 核验、人类批准，形成不可静默覆盖的冻结版本。
禁止：读取真实性能后回填 delta、O、分组、参照或检验族。

### P2：A2 统计生产资格

进入条件：合成合同已通过，候选 simultaneous-CI 实现可定位。
工作：用参考实现或预先声明的模拟方案验证覆盖率、NA family slot、完整调查域、max-gap 投影和 precision 输出；锁定生产算法及版本。
退出条件：Reviewer 独立重跑测试与覆盖 QA，确认 Holm 与 simultaneous CI 没有混用，主管签发生产资格。
说明：通过软件测试不等于 NHIS 结果成立。

### P3：A3 冻结真实扫描

进入条件：P1、P2 被正式接受；2023 replay 规范、模型/源码/预测/order hash 全部冻结。
工作：2023 只作发现；按预注册规则最多冻结 5 个新 O；2024 仅依已声明规则回顾性复核。首先比较固定模型集合的 anchor 与 expanded 结论，再报告方法相对匹配 baseline 的差异变化、绝对组性能、总体 BA、风险质量和其他 O 的恶化。
退出条件：全候选分母、负结果、不可估、精度、普通/同时 CI、Q1 与 Q3/Q4 独立家族、判断迁移和绝对权衡均完整；没有结果驱动的 registry 修改。
停止条件：任何 hash/order/域合同失败、年度角色混淆或真实数据权限冲突。

### P3.5：提前论文证据包

进入条件：P3 经 Reviewer 核验，但尚未决定 A4。
必须生成：

1. 可直接进入文稿的 Methods 初稿，明确调查设计、逐 O 域、时间角色、统计家族、delta/三态和限制；
2. 候选 O 流程表，包含 atlas 分母、排除理由、冻结 O、嵌套簇、支持度和精度；
3. 第一版核心结果图，优先展示 anchor 与 expanded 判断迁移及绝对权衡，而非只画 gap 排名；
4. claim-evidence 表，为每条拟写主张列出 estimand、年度、模型/panel、证据文件、区间、限制和允许措辞；
5. A4 `GO/NO-GO` 决策材料，说明新增训练是否回答必要科学问题，而非只改善版面或追求显著。

退出条件：作者能明确哪些主张被支持、被否定或证据不足；Reviewer 确认图表和文字没有超过证据。

### P4：A4 有界增强（非必需）

进入条件：P3.5 的 claim-evidence 缺口确实需要针对性训练，且人类记录 `GO`。
工作：最多 3 个新 O；固定 X、部署合同、训练/阈值政策和独立统计家族；所有新资产版本化。
退出条件：无论正负，完整报告性能、失败、不可估和额外复杂度。
`NO-GO` 是允许的正常结论，不影响继续走验证和论文整合。

### P5：A5 2025 一次性验证

进入条件：O、delta、模型、panel、指标、家族、源码、输入 hash、记录顺序全部冻结；真实数据权限和人类 release decision 有记录。
工作：只执行一次冻结验证；不得据 2025 改规则。
退出条件：验证、未复现、不可估和精度全部披露。若没有合法可用的 2025 数据，则必须在 decision log 中重定论文范围，删除“未见 2025 验证”主张，不能用 2024 替代。

### P6：论文整合与内部审稿

进入条件：P3.5 完成；P4/P5 按各自决定完成、跳过或诚实缩小范围。
工作：完成摘要、引言、Methods、Results、Discussion、局限、数据/代码可用性、伦理和 AI 披露；生成主表、主图、补充材料、分析 manifest 和可重现说明；建立与 fairness gerrymandering、审计覆盖和医疗调查推断文献的创新边界。
退出条件：所有数字由冻结产物生成，claim-evidence 无悬空项，Reviewer 完成统计/代码/叙事三线复核，所有实际作者批准。

### P7：投稿就绪与投稿

进入条件：P6 内审通过。
工作：由人类选择目标期刊；按期刊格式完成标题页、投稿信、作者贡献、利益冲突、资助、伦理、数据和代码声明；对匿名材料做隐私检查；保存最终版本 hash。
退出条件：Human/Supervisor 明确批准投稿，投稿回执被保存。Agent 不得把“上传页面可见”写成“投稿完成”。

### P8：审稿与修订

进入条件：收到编辑或审稿意见。
工作：建立逐条 response matrix；任何新增分析先经过新的 gate、estimand 与家族审查；不得为满足审稿意见而事后重定义原确认性分析。
退出条件：修订包经作者批准并提交，或记录拒稿/转投决定。发表与否仍为外部结果。

## 4. 首篇最小证据包

论文主体只要求以下四块闭环：

1. 审计覆盖、候选准入和证据边界；
2. expanded audit 相对 anchor audit 的增量发现及精度；
3. 对同一固定方法的有效性判断是否改变；
4. 冻结验证与绝对性能/风险质量权衡。

第二数据集、无界模型扩展或更多去偏算法不是首篇默认条件。只有它们能解决 claim-evidence 表中的必要缺口，才另立 gate。

## 5. 投稿就绪定义

同时满足下列条件才可称为“submission-ready”：

- 研究问题、estimand、年度角色、panel、O、delta、指标和统计家族有冻结版本；
- 全部真实运行有输入/源码/模型/预测/order/output hash 和不可覆盖 manifest；
- 复杂调查域、同时区间、多重检验、precision 和绝对性能权衡通过独立复核；
- Methods、O 流程、表图、claim-evidence、补充材料与可重现说明一致；
- 负结果、不可估、已知 2024 身份、A4/A5 实际执行状态和局限完整披露；
- 伦理、数据权限、作者贡献、资助/冲突、AI 使用和数据/代码可用性由真实责任人确认；
- Reviewer 无未关闭的 critical finding，全部作者批准最终稿与目标期刊。

该定义不包含“必须显著”“FairBias 必须获胜”或“必须录用”。

## 6. 报告节奏与升级规则

Worker 每个 gate 只提交协议 Section 9 的证据报告，不自称接受。Reviewer 对新增文件、diff、hash、测试、数据访问和主张边界独立复核，并给出 Accept/Repair/Reject 建议。遇到应用场景、delta、正式 O、伦理/作者责任、受限数据权限或改变 estimand 的事项，集中提交 Human/Supervisor；常规可逆技术工作继续，但相关下一 gate 保持关闭。
